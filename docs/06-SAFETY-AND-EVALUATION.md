# Safety and evaluation

Deterministic backend controls remain active with or without an LLM or Model Armor. Missing/stale ingredient or cross-contact facts produce staff review, never an absence claim or safety guarantee. Dietary constraints are separately checked. Model confidence is not evidence. Allergy profile changes require an explicit separately audited action.

Order confirmation rechecks eligibility, price, inventory, and opening against the bound preview; state transitions are allowlisted and keys are idempotent. Manager decisions are audited; acceptance never means execution. Staff interactions are visibly synthetic. Errors do not produce demo success.

Prompt injection cannot authorize tools: narrow tools and backend checks govern. User/model text is escaped by React rendering and not used for SQL or code. Configured calls have finite timeouts. Synthetic data only; no real customer records or third-party writes.

Evaluation separates deterministic policy tests from optional model evaluation. The backend suite includes a small versioned menu-retrieval golden set for the canonical allergy request, hot espresso selection, and an unsupported smoothie query. Policy cases cover allergen conflict, unknown/stale evidence, diet, budget/missing price, unknown item, closed café, missing queue, order failure, duplicate confirmation, changed price/stock, prompt injection/tool scope, learning persistence/precedence, allergy non-learning, manager approval, owner math, location data handling, and visible provider status. This is not an LLM-as-judge or broad semantic retrieval evaluation. Failed/rejected responses may become candidates; a human must approve a golden case and regression checks must pass before prompt/policy promotion.
